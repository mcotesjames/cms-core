# Component rules

- Selected publications use a native CSS scroll-snap list on mobile and a grid on desktop, keeping each card a single link. Why: touch scrolling and keyboard focus reveal items without extra carousel state or nested controls.
- Investment cards use one controlled active ID, a native disclosure Button and a separate website anchor with hidden backs removed from keyboard/accessibility navigation. Why: hover, keyboard and touch share a single-open interaction without nested interactive controls.
- Investment cards use the controlled open state for both slide reveal and the card's full-border colour change, with sector/stage sourced from the company row on the front. Why: pointer, keyboard and touch share the same presentation without altering CMS content or filtering.
- The page background ports the theme's six-field shader and canvas-backed pointer trail into R3F, fixed behind every public page; palette uniforms read global CSS tokens. Why: preserves source visuals and interaction while retaining React lifecycle cleanup and reduced-motion support.
- `PageBackground` is mounted once in the root layout (public paths only, `hasPageBackground`), never inside a route; FluidBackground calls `markBackgroundReady` after its first painted frame and the intro curtain waits on `whenBackgroundReady` (with a timeout) before lifting, with letter reveals paused while it covers. Why: a per-route canvas rebuilt on every navigation and the static CSS gradient showed until it painted; rendering is suspended inside a view-transition update, so the new page can't wait for a fresh canvas.
- Horizontal pillars use a client-loaded GSAP ScrollTrigger timeline with a final native SVG symbol mask, switching to vertical cards below the source breakpoint and cleaning up on navigation. Why: matches the theme's unified slide/reveal sequencing without nested scroll areas or server-side browser imports.
- Stacking cards use a dedicated client-loaded GSAP pinned viewport with overlapping absolute cards; reduced motion returns to document flow. Why: preserves theme stacking sequence without sticky-card drift.
- Biography uses CMS hotspot coordinates against the full section canvas on desktop and inline accordion rows on mobile. Why: matches CMS positioning semantics rather than positioning points on the portrait.
- Transition scroll resets synchronize the active Lenis instance after the route commit and before the incoming snapshot; completion only resumes scrolling. Why: article parameter changes reuse Lenis, and a post-swipe reset exposes a visible jump.
- Investment card logos show in their own colours (no CSS filter). Why: the client wants brand logos as supplied; logos must be uploaded in a version that reads on the white card.
